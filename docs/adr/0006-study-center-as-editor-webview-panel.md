# 0006. 听写和可视化放在编辑器标签页「学习中心」

- 状态：已接受
- 日期：2026-11-26
- 相关：[设计文档 · 界面与交互](../design/0.4-daily-dictation.md#界面与交互)

## 背景

听写需要输入框、提示和反馈区；复习曲线、待复习量、复习列表需要较大的绘图和表格空间。现有界面有：

- 底部面板里的 CodeVocab 发音面板（webview view），高度通常只有几行代码那么高，而且和终端、输出共用一块区域。
- 状态栏，只能放一小段文字。

## 决策

新建一个编辑器标签页「CodeVocab 学习中心」（`createWebviewPanel`），听写、概览、曲线、复习列表、成就都放在这里。

- 全局只有一个实例。已打开时调用 `reveal()` 切过去，不会重复创建。
- 从状态栏任务项或“开始听写”打开时直接进入听写，从命令或面板按钮打开时进入概览。
- 用户像关文件一样关闭它；插件不会自动关闭。`Esc` 只退出当前这组听写。
- 不开启 `retainContextWhenHidden`，以节省内存。听写进度放在插件端，标签页切走再切回时重新拉取。
- 发音面板和状态栏保持现状，只增加入口按钮和任务项。

没选放在底部面板：太矮，放不下输入框和图表；用户也常常把面板收起来。

没选放在侧边栏：太窄，图表和表格都挤。

## 后果

- 听写时编辑器区域被占用，正好符合“听写是专门的练习、不和写代码同时进行”的定位。
- 学习中心的 webview 需要自己调用 `speechSynthesis` 发音，和发音面板是两套播放；听写开始时要暂停后台播放，避免同时出声。
- webview 的 `speechSynthesis` 需要用户先交互才能出声，第一题需要用户点一下「开始」。
- 是否注册 `WebviewPanelSerializer`，让 VS Code 重启后恢复学习中心标签页，留到实现时再定。
