# 0002. 复习卡片以小写单词为 key，跨词库共用

- 状态：已接受
- 日期：2026-11-26
- 相关：[设计文档 · 数据模型与存储](../design/0.4-daily-dictation.md#数据模型与存储)

## 背景

每个学过的词要有一张复习卡片，需要一个唯一标识。现状：

- 内置词库和自定义词库里的词条都没有 id 字段。
- 不同词库之间有大量重复词，比如 abandon 同时出现在四级、六级、考研、雅思里。
- 自定义词库的 id 目前都是 `custom`，无法区分不同文件。

可选方案：

1. `词库 id + 单词` 作 key，每本词库各算各的。
2. 单词本身作 key，跨词库共用一张卡片。
3. 给每个词条生成稳定 id（比如内容哈希）。

## 决策

用**小写单词本身**作 key，跨词库共用一张卡片。卡片里另存“首次来源词库 id”，只用于复习列表的筛选。

没选方案 1：用户在四级里已经记住的 abandon，切到六级时要从头再学一遍，复习量和到期提醒也会重复计算，不符合“记住的是这个词”的直觉。

没选方案 3：词条的释义、音标会随词库更新而变，哈希不稳定；而用户真正记的是拼写，拼写本身就是最稳定的标识。

## 后果

- 换词库不丢进度；同一个词在任何词库里出现，复习状态都一致。
- 大小写不同的词（比如 `Linux` 和 `linux`）视为同一个词。目前词库里没有需要区分大小写的情况，以后遇到再单独处理。
- 同一个词在不同词库里的释义可能不同（编程语境 vs 通用语境）。听写题干用当前词库的释义，卡片本身不存释义。
- 自定义词库的 id 要改为 `custom:<文件名>`，否则来源筛选无法区分。
- 「程序员易读错词」词库暂时不进听写，不生成卡片（见设计文档“已定事项”）。
