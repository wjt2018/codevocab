# 0001. 复习调度采用 FSRS，不用固定间隔表

- 状态：已接受
- 日期：2026-11-26
- 相关：[设计文档 · 复习调度](../design/0.4-daily-dictation.md#复习调度)

## 背景

0.4.0 要给每个学过的词安排复习时间，并画出遗忘曲线。常见做法有两种：

- **固定间隔表**：比如 5 分钟、30 分钟、12 小时、1 天、2 天、4 天、7 天、15 天，每复习一次往后挪一档。很多背单词插件用这种方式，号称“艾宾浩斯遗忘曲线”。
- **自适应算法**：根据每次作答的好坏调整间隔，比如 SM-2（Anki 早期算法）和 FSRS（Anki 23.10 起内置的新算法）。

固定间隔表的问题：

- 不区分答得好和答得差。只能往后挪，不会因为忘了而缩短间隔。
- 没有“记忆保持率”这个量，画不出真实的遗忘曲线，只能画示意图。

## 决策

采用 FSRS，直接使用开源库 [`ts-fsrs`](https://github.com/open-spaced-repetition/ts-fsrs)（MIT 协议，纯 TypeScript，没有运行时依赖）。

- 听写结果映射为 FSRS 的四个评分：Again / Hard / Good / Easy。
- 目标保持率默认 0.9，可配置 0.8–0.95；最大间隔 365 天；开启间隔随机抖动。
- 权重先用库的默认值，保留完整作答日志，以后可以训练个性化权重。

没选 SM-2：它只有“难度系数”，没有稳定性 S 和保持率 R，同样画不出可信的遗忘曲线；而且业界已经在从 SM-2 迁移到 FSRS。

没选自己实现 FSRS：公式和参数还在演进（FSRS-4.5、5、6），自己实现容易和社区版本脱节。

## 后果

- 每个词都有稳定性 S、难度 D 和到期时间，可以随时算出当前保持率 R，遗忘曲线、复习列表排序和待复习量预测都基于它。
- 新增一个运行时依赖，需要改打包方式，见 [ADR 0005](0005-bundle-with-esbuild.md)。
- R 的计算公式随库版本变化。代码里统一调用库自带的函数，不自己写死公式。
- 升级 `ts-fsrs` 的大版本前，要确认卡片字段和评分枚举是否兼容，必要时写数据迁移。
