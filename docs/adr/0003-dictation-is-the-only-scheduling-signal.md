# 0003. 只有听写结果更新复习调度

- 状态：已接受
- 日期：2026-11-26
- 相关：[设计文档 · 复习调度 · 更新时机](../design/0.4-daily-dictation.md#更新时机)

## 背景

CodeVocab 的核心场景是写代码时后台播放单词。引入 FSRS 后要决定：哪些行为算一次“复习”，会改变卡片的稳定性和到期时间？

候选信号：

- 后台播放、状态栏轮播（用户可能根本没在听）
- 用户手动标记“太简单”（主观判断，常常高估自己）
- 听写作答（有客观的对错和用时）

## 决策

只有听写作答会更新 FSRS 卡片：

- 后台播放和状态栏轮播只累计“听过次数”，不改调度。
- 手动标记“太简单，不再复习”时，直接把词标为已排除，不走 FSRS。
- 一组听写内答错后的重考只用于巩固，不再改变评分。
- 听音选义是选择题，答对时最高只评 Good，避免稳定性涨得虚高。

没选“播放也算一次低权重复习”：听过不代表记住了。把它算进去会让间隔越拉越长，而用户实际上可能一个词都写不出来，曲线就失真了。

## 后果

- 复习数据和曲线都基于真实的回忆结果，可信度高。
- 只听不写的用户不会产生任何复习数据，学习中心是空的。需要用状态栏任务项和每日提醒引导用户去听写。
- 听写成为产品的核心环节，它的体验（判定规则、提示、键盘操作）要做得足够顺手。
